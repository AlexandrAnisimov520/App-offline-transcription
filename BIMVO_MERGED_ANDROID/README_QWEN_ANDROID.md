# BIMVO: локальная «Выжимка» Qwen3

Основа: `BIMVO_MERGED_RECORDING_MVP.zip`, предоставленный пользователем. Дизайн, запись M4A, импорт, SQLite-журнал, плеер, таймкоды, редактирование, ключевые цитаты и экспорт сохранены. Добавлена кнопка **«Выжимка · Qwen3»** под расшифровкой.

## Комплект для экспертов

Готовый APK включает модель Qwen3-1.7B Q4_K_M. При первом запуске приложение копирует её в своё хранилище блоками по 64 КиБ, проверяет размер и SHA-256 и сохраняет готовый файл. После этого llama.cpp использует его через mmap. Порядок установки описан в `START_HERE_RU.md`.

Чтобы пересобрать этот вариант, извлеките из APK папку `assets/models` в отдельный каталог, например `expert-assets/models`. В корне проекта запустите `gradlew.bat :app:assembleDebug -PbundledQwenAssets=expert-assets`. В APK файл модели хранится без сжатия. Лицензия модели приложена в `QWEN_LICENSE.txt`.

Источник модели — [ggml-org, Qwen3-1.7B Q4_K_M](https://huggingface.co/ggml-org/Qwen3-1.7B-GGUF/blob/daeb8e2d528a760970442092f6bf1e55c3b659eb/Qwen3-1.7B-Q4_K_M.gguf).

## Сборка с ручным импортом модели

1. Распакуйте проект в короткий путь латиницей, например `C:\BIMVO`. Android CMake/NDK на Windows плохо работают с кириллицей и очень длинными путями.
2. Откройте корень `BIMVO_MERGED_ANDROID` в Android Studio. Нужен JDK 17.
3. SDK Manager: установите Android SDK Platform 35, Build Tools 35.0.0, NDK **28.2.13676358**, CMake **3.31.6**. Примите лицензии SDK. SDK также должен находиться в пути латиницей.
4. Создайте `local.properties`, например `sdk.dir=C:/Users/User/AppData/Local/Android/Sdk` (укажите реальный SDK).
5. PowerShell в корне проекта: `.\gradlew.bat :app:assembleDebug`. APK: `app/build/outputs/apk/debug/app-debug.apk`.
6. Установите APK на 64-битный Android-телефон (arm64-v8a, Android 8+). По умолчанию собирается только ARM64, чтобы уменьшить APK. Для отдельной сборки эмулятора: `.\gradlew.bat :app:assembleDebug -PllmAbi=x86_64` (эта ABI не входит в поставляемый APK). 32-битные устройства не поддерживаются.
7. Скопируйте на телефон **Qwen3-1.7B Q4_K_M в GGUF**, например из https://huggingface.co/ggml-org/Qwen3-1.7B-GGUF . Веса в ZIP/APK не включены. Не нужны Python, Windows exe или запущенный сервер.
8. Откройте запись с готовой расшифровкой → **«Выжимка · Qwen3» → «Модель GGUF»** → выберите файл. Дождитесь сообщения об успешном копировании. Затем снова откройте «Выжимка» → **«Создать конспект»**.

Модель копируется в `files/models/Qwen3-1.7B-Q4_K_M.gguf` внутри приложения. Не кладите гигабайтную модель в assets. Имя выбранного файла может быть любым: после копирования используется фиксированное внутреннее имя. Понадобится свободное место под оригинал и копию; при замене старая модель сохраняется до завершения копирования. Проверяются GGUF magic и минимальный размер, движок проверяет архитектуру qwen3 при загрузке. Повреждённые веса могут потребовать повторного выбора корректного файла. Внешние исходники не удаляются.

Для debug-APK возможна установка через adb:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb push Qwen3-1.7B-Q4_K_M.gguf /data/local/tmp/qwen.gguf
adb shell run-as com.bimvo.app mkdir -p files/models
adb shell run-as com.bimvo.app cp /data/local/tmp/qwen.gguf files/models/Qwen3-1.7B-Q4_K_M.gguf
```

Основной рекомендуемый способ — кнопка выбора GGUF. ADB-способ только для debug, поскольку release не разрешает run-as.

## Что реализовано

- Отдельный Android library-модуль `llm`, Java API `LlamaSession`, настоящий C++ JNI-мост к llama.cpp. CPU, mmap по умолчанию; GPU и сеть не используются.
- Вендорены нативные исходники и MIT-лицензия llama.cpp. Ничего не скачивается из CMake при сборке нативного модуля. Gradle/SDK при первоначальной настройке требуют интернет.
- Qwen3 ChatML, `/no_think` и префикс закрытого think-блока, сэмплирование top-k 20 / top-p 0.8 / temperature 0.7. Профиль для 4 ГБ: контекст 1024, вывод до 192 токенов, до 2 CPU-потоков, batch 64 / microbatch 32.
- Загрузка и генерация вне UI, обновление текста по токенам, честный счётчик вместо выдуманного процента. «Отмена»/закрытие диалога отменяет загрузку через progress callback, decode через abort callback. Освобождение sampler/context/model выполняется на рабочем потоке. Новые задания сериализованы даже при повороте экрана.
- Результат хранится в приватных SharedPreferences отдельно от расшифровки, по ID записи и SHA-256 текста. После редактирования расшифровки прежний результат не показывается для нового текста. Новый импорт модели очищает кэш выжимок. JSON/TXT/SRT экспорт остаётся исходным экспортом расшифровки; выжимку можно выделить и скопировать в диалоге.
- Микрофон, аудио и база данных не передаются в llama.cpp: Qwen получает только готовый текст.

## Ограничения и ошибки

- Это интеграция LLM для **текста**. ASR и диаризация в исходном MVP не подключены: новая запись сама не превращается в текст. Используйте существующий импорт настоящего JSON-результата ML или демонстрационную расшифровку (она остаётся помеченной как демо).
- Слишком длинная расшифровка вызывает явную ошибку контекста: текст не обрезается, автоматического разбиения/сведения частей пока нет. Подайте короткий разговор/фрагмент. Лимит 1024 считается токенизатором модели, включая системную инструкцию и резерв 192 токенов.
- При достижении 192 токенов результат помечается как потенциально незавершённый. Качество, фактичность и скорость Qwen зависят от модели и телефона.
- Держите экран с диалогом открытым до конца: он не гаснет при генерации. При уничтожении Activity/повороте задача отменяется; начните её заново. Foreground service для генерации не добавлен. Android может завершить процесс при недостатке RAM; Java-ошибка не способна перехватить системное убийство процесса.
- Ошибки загрузки, неподходящей архитектуры, контекста и native-library отображаются в диалоге. Отмена может дождаться текущей операции чтения/вычисления, она не является мгновенным прерыванием любого системного вызова.
- Целевое устройство — 4 ГБ общей ОЗУ. Перед генерацией проверяются lowMemory и свободная физическая память: требуется не меньше размера GGUF + 384 МиБ. Это консервативная оценка, не измеренный пик; при отказе закройте другие приложения. Файлы больше 1,5 ГиБ и модели больше 2 млрд параметров не допускаются: нужен Qwen3-1.7B Q4_K_M.
- Во время загрузки и генерации память проверяется раз в секунду. При системном lowMemory или остатке меньше 128 МиБ задача получает сигнал отмены и UI показывает причину остановки. Это дополнительная защита, но ОС способна убить процесс раньше следующей проверки.
- Веса загружаются через `LLAMA_LOAD_MODE_MMAP`, без mlock (ОС может освобождать файловые страницы); K-кэш Q8_0, V-кэш F16. Квантование V не включено, поскольку оно требует Flash Attention, поддержка которого зависит от CPU. Малые batch/ubatch уменьшают вычислительный буфер. Отключены runtime-repacking, KleidiAI и extra buffer types для весов. GPU не используется. Выходной буфер ограничен одной позицией logits, native-код оптимизирован в Release даже внутри debug APK. Копирование GGUF использует буфер 64 КиБ, файл целиком в Java heap не читается. Одновременно разрешена только одна нативная задача, все веса и контекст освобождаются после неё.
- Уменьшение контекста сокращает длину допустимой расшифровки. Не гарантируется отсутствие системного убийства процесса на всех телефонах с 4 ГБ: обязательна реальная проверка в авиарежиме, включая нагрузку другими приложениями.
