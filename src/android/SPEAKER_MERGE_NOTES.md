# Объединение BIMVO и финальной диаризации

> Исторические заметки первоначального объединения. Актуальный статус: [CHECKPOINT_20261107.md](CHECKPOINT_20261107.md).
> Сейчас версия 0.5-speakers/versionCode 5, production-порог 0.52; указанные ниже 0.4 и 0.32 устарели.
> «Финальная» в заголовке — название исходного архива, не подтверждение качества диаризации.

Рабочий проект: `D:\Nuclear-hack-Bimboteam\BIMVO_MERGED_ANDROID`.
Локальная ветка: `codex/integrate-speaker-diarization`. Версия приложения: `0.4-speakers`, versionCode 4.
Источник диаризации: `D:\BIMVO_speaker_diarization_final.zip`, распакован в `speaker_benchmark` рядом с Android-проектом.

## Что объединено

Сохранены запись и импорт, GigaAM ASR, плеер, кликабельная карта, библиотека, переименование/удаление и встроенный Qwen с сохранением, копированием и TXT-экспортом конспекта.

Управление записью находится в карточке, где пользователь нажал «Записать разговор». При старте карточка показывает таймер, уровень микрофона и остановку. Глобальная верхняя полоса записи удалена. На других экранах небольшой маркер в логотипе возвращает к карточке.

Новый конвейер: PCM mono 16 кГц → Silero VAD → ERes2NetV2 → глобальная кластеризация → распознавание реплик GigaAM. Сессии VAD, голосовой модели и ASR закрываются последовательно, чтобы не держать все три модели одновременно.

В APK добавлен portable FP32 BASIC `speaker_embedding_v2_basic.onnx` размером 71 425 388 байт, SHA-256 `94b4e4821e227503131df2be2b59084e3a6807e624a73c49144f0cc8cf5066d9`. Gradle проверяет его перед сборкой. Модель читается из несжатого ресурса через mmap. Веса Qwen и ASR остаются в APK.

## Алгоритмы

- Kaldi fbank: 80 каналов, Povey 25 мс, шаг 10 мс, FFT 512, DC removal, preemphasis 0,97, без dither, вычитание среднего по каждому каналу окна. Нормализованный PCM16 делится на 32768.
- Вход ERes2NetV2: `x [1,T,80]`; выход `embedding [1,192]`. ORT CPU, EXTENDED_OPT, intra=2/inter=1.
- Автоматический VAD: пороги входа/выхода 0,5/0,35, пауза завершения 200 мс, поля по 80 мс. Фрагменты короче 100 мс не используются.
- Внутри речи — двухсекундные окна анализа с шагом 1 с. Их участки ответственности разделяются по серединам центров: аудио не дублируется в ASR. Соседние участки одного голоса объединяются, максимум ASR-чанка — 23,5 с.
- Кластеризация перенесена из архива: complete linkage, cosine distance 0,32, опорная речь от 1,2 с; короткие реплики присоединяются при similarity ≥0,45 и отрыве ≥0,05. Неуверенные результаты остаются `speaker_unknown`.
- Для длинных записей кластеризация использует до 512 равномерно выбранных опорных окон всей записи. Остальные окна присоединяются к центрам; объём матрицы расстояний ограничен.

## Библиотека и повторная обработка

База версии 3 добавляет `audio_chunks.speaker_id`. Миграция с 1 и 2 сохраняет записи и старую расшифровку. Новые результаты записываются в чанки; окончательная расшифровка заменяется одной транзакцией только после успешной обработки всех чанков. Отмена или ошибка сохраняет предыдущий текст. План и метки голосов переживают остановку процесса.

Старые записи не переписываются автоматически. В меню `⋮` есть «Обработать с диаризацией» с подтверждением. После завершения метки появятся в тексте, карте и экспорте. Уже сохранённый конспект не пересоздаётся, согласно принятому пользовательскому сценарию.

- Контрольный fbank из архива: max abs `6,6280e-5`, RMSE `7,4936e-6`; все элементы проходят atol=1e-4/rtol=1e-3.
- Контрольный embedding через Python ONNX Runtime на Java-признаках: cosine ≈1,0, выше требования 0,9999.
- Регрессии production Java: три различных голоса, возвращение после паузы, неизвестная короткая реплика, неоднозначная короткая реплика, невалидные векторы, complete-linkage bridge, ограничение опорных окон, отмена и покрытие без повторов/пропусков — пройдены.
- На двух WAV из архива с ПОДГОТОВЛЕННЫМИ границами Java и Python дают одинаковые метки. `clean`: 3 голоса, DER 1,9400%; `overlap`: 3 голоса, DER 4,7619%. Это проверка переноса, не измерение автоматического VAD на живом разговоре.

- Существующие тесты: 69 проверок основной логики, JSON/Unicode-контракт, 7 проверок SQLite и синтаксический разбор 32 Java-файлов пройдены. Старый QA-harness обновлён под текущие четыре таблицы схемы, вместо устаревших трёх DDL-выражений.
- Финальный APK собран повторно после последних правок: BUILD SUCCESSFUL, 60 задач. ZIP/CRC и состав ресурсов проверены. Веса Qwen, GigaAM, Silero и ERes2NetV2 включены.

## Практические ограничения

Если для отдельного голосового фрагмента ASR не распознал слова, в расшифровке остаётся явная пометка «Речь не распознана», чтобы не терять голосовой интервал на карте. Такие пометки не передаются в Qwen как исходный текст. Если слова не распознаны во всей записи, обработка завершается ошибкой и прежний текст сохраняется.

Архив не содержит модели Pyannote segmentation, хотя отчёт описывает отдельный эксперимент с ней. Здесь используется существующий Silero и окна анализа, поэтому одновременные голоса не разделяются на отдельные аудиодорожки. Смены без пауз, шум и очень короткие реплики могут давать ошибки или «Говорящий не определён». Метки спикеров не являются идентификацией реальных имён, а границы реплик не являются выравниванием отдельных слов.

Полный APK больше 1,7 ГБ. На компьютере нужны дополнительные гигабайты для упаковки и LFS: сохранённые в Git кэши могут создавать большие временные копии при фоновом просмотре изменений IDE.

В текущем локальном Git-индексе для 748 уже отслеживаемых файлов `app/build`, `llm/build`, `llm/.cxx`, `.gradle` временно выставлен `assume-unchanged`, чтобы фоновая проверка IDE не создавала повторные гигабайтные копии LFS. Файлы остаются на диске и в истории Git. Перед следующим коммитом новых кэшей этот локальный флаг нужно снять (`git update-index --no-assume-unchanged` для соответствующих путей), имея достаточно свободного места. Исходники этим флагом не скрываются.

Если Gradle из автоматической сессии выдаёт `Unable to establish loopback connection`, в этой среде помогло задать короткую папку временных сокетов Java в текущем PowerShell-процессе:

```powershell
New-Item -ItemType Directory -Path D:\Gradle\tmp -Force
$env:TEMP='D:\Gradle\tmp'
$env:TMP='D:\Gradle\tmp'
$env:JAVA_TOOL_OPTIONS='-Djava.io.tmpdir=D:/Gradle/tmp -Djdk.net.unixdomain.tmpdir=D:/Gradle/tmp'
.\gradlew.bat :app:assembleDebug
```
