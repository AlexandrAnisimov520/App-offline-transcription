# BIMVO — диаризация CAM++

Открывайте эту папку в Android Studio: здесь полный Android-проект BIMVO, а не отдельный патч.
Основа: ветка `codex/parakeet-600m`, commit `a97d0c8ccfceb4a9243e196090172d1bab2ebfdd`.
Исходный алгоритм: commit `c773631c4933a709597f0a61d5e9c6ad875991ab`.

## Что подключено

- CAM++: настоящие веса `app/src/main/assets/models/diarization/embedding.onnx` уже в архиве.
- Silero VAD v5 и исходные параметры: threshold 0.4, min silence 0.25 с, min speech 0.15 с, max speech 20 с.
- Поиск смены голоса: окна 1.5 с, шаг 0.25 с, порог 0.3.
- Исходная глобальная average-linkage кластеризация: порог 0.55, уточнение центроидов, объединение малых кластеров и адаптивное слияние 0.65–0.9.
- Исходные WordAligner и TranscriptAssembler: привязка слов к спикерам, сглаживание, сборка реплик, стабильная нумерация по первому появлению.
- Реплики со speaker_id, start_ms, end_ms и текстом поступают в существующий интерфейс, проигрывание и экспорт BIMVO.
- Русский GigaAM-v3 E2E CTC, английский Parakeet, определение языка и Qwen для изложения сохранены.

## Порядок обработки

Декодирование в PCM mono 16 кГц → нормализация как в исходном алгоритме → VAD → распознавание речи → CAM++ и глобальная кластеризация → распределение слов между спикерами → сохранение реплик.

ASR получает запас 100 мс по краям речевого сегмента, как в исходном алгоритме. Русские метки получаются из индексов кадров CTC с пересчётом по длительности аудио и числу выходных кадров (формула GigaAM compute_frame_shift); английские — из timestamps Parakeet. Это модельные оценки времени, а не вручную размеченный эталон.

Распознавание каждого завершённого сегмента и его слова сохраняются одной транзакцией. После отмены можно продолжить: сохранённые сегменты ASR повторно не распознаются. Если остановлена диаризация, она пересчитывается по всей записи, используя готовый текст. Старые завершённые расшифровки автоматически не заменяются — для них запустите повторную обработку.

## Сборка на Windows

1. Распакуйте архив целиком. Откройте папку `BIMVO_DIARIZATION_ANDROID` в Android Studio.
2. Выберите Gradle JDK 21. Установите Android SDK 35, Build Tools 35.0.0, NDK 28.2.13676358 и CMake 3.31.6 (нужны сохранённому модулю Qwen).
3. Дождитесь Gradle Sync и выполните в терминале проекта:

```powershell
.\gradlew.bat :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

При первой сборке нужен интернет НА КОМПЬЮТЕРЕ: Gradle автоматически скачает и проверит веса GigaAM, Parakeet, Whisper LID, Qwen и зависимости. Объём моделей — около 2.3 ГБ; резервируйте место также под SDK, NDK и сборку. Веса CAM++, Silero v5 и Sherpa AAR уже включены. Крупные ASR/LLM-веса не вложены в ZIP. После сборки модели находятся в APK, обработка на телефоне офлайн.

## Отличия адаптации

ASR и LLM не заменялись на модели исходного проекта. Вместо хранения всей записи в FloatArray аудио читается небольшими окнами из PCM-файла. Нормализация сохраняет производный PCM с точностью 16 бит; исходный аудиофайл не меняется. Пул CAM++ сохраняет исходный подход: 2–4 однопоточных экстрактора. Алгоритм кластеризации и его пороги не перекалиброваны. Добавлены проверки отмены и освобождение уже созданных экстракторов при ошибке инициализации.

Из исходного проекта не переносились интерфейс, RNNT ASR, LiteRT-LLM, часы и прочие функции. Pyannote и ERes2NetV2 в активной цепочке диаризации не используются; старые Java-классы/материалы BIMVO оставлены для совместимости исторических QA и не вызываются новой цепочкой.

## Статус проверки

Смотрите `qa/DIARIZATION_VALIDATION.md`. Компиляция Java/Kotlin и тесты пройдены. Полный APK в этой среде НЕ собран: Gradle не смог обратиться к репозиториям плагинов (`Network is unreachable`). Испытания на Android-телефоне и итоговый DER всего приложения не проведены. Гарантировать отсутствие любых ошибок без этих проверок нельзя.

После сборки проверьте RU/EN диалоги, одного спикера, возвращение спикера, отмену на ASR/диаризации, возобновление, проигрывание по меткам, JSON/SRT и создание изложения. Проверьте также обновление поверх вашей предыдущей версии (SQLite 2/3 → 4).

Исходники перенесённых компонентов сохранены в `third_party/diarization`; происхождение — в `THIRD_PARTY_DIARIZATION.md`. Этот README описывает новую версию; прежние отчёты и инструкции в проекте относятся к предыдущим экспериментам.
