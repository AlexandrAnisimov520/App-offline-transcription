# BIMVO · интеграция в Android ARM

1. Положите `speaker_embedding_v2_basic.onnx` в assets либо в локальный каталог моделей. Его SHA-256 и хеш FP32-кандидата приведены в `reports/graphs.json`. Для ORT Java скопируйте asset потоком во внутренний каталог приложения, проверьте хеш и передайте путь к файлу в `createSession`. Используйте CPU Execution Provider из Android AAR `com.microsoft.onnxruntime:onnxruntime-android` с ABI `arm64-v8a`. Если приложение уже использует ORT внутри Sherpa-ONNX, избегайте второй копии нативной библиотеки. FP32 ONNX использует стандартные узлы opset 13. Для первого прогона используйте `EXTENDED_OPT` во время создания сессии. Проверьте `ALL_OPT` непосредственно на телефоне.
2. Создайте `OrtSession` один раз для обработки записи и переиспользуйте её для всех окон. Сессия принимает имя `x`, тип `float32`, форму `[1,T,80]` и выдаёт `embedding` формы `[1,192]`. Установите `interOpNumThreads=1`, последовательно измерьте `intraOpNumThreads=1,2,3,4`. Для каждого окна освобождайте входной `OnnxTensor` и `OrtSession.Result` после копирования вектора. Закрывайте сессию после последнего окна или при отмене обработки.
3. Сведите запись к mono и 16 кГц. Для PCM16 используйте `sample / 32768f`. Признаки можно вычислять через kaldi-native-fbank по JNI или через подходящий существующий нативный слой. Для каждого окна используйте Kaldi log-power fbank, 80 mel-каналов, окно Povey 25 мс (400 сэмплов), шаг 10 мс (160 сэмплов), `snip_edges=true`, `dither=0`, preemphasis 0,97 и удаление DC. Нижняя mel-граница 20 Гц, верхняя — Найквист. Вычтите среднее каждого канала по времени текущего окна. Проверяйте полную цепочку через фикстуру ниже.
4. Перенесите подготовку границ из `intervals.py` и глобальную кластеризацию из `clustering.py` в Kotlin или C++. Если приложение уже содержит совместимый `segmentation.onnx`, его локальные выходы можно декодировать по `pyannote_segments.py`. На длинных записях храните PCM на диске и читайте окна по индексам. Применяйте L2-нормализацию эмбеддингов и косинусное расстояние. Complete linkage использует максимальное попарное расстояние между двумя кластерами. Метки назначайте после извлечения эмбеддингов из всей записи. Для участков с `UNKNOWN` храните отдельный статус и исключайте их из вычисления центроидов. Привязывайте транскрипт к готовой временной шкале спикеров по пересечению интервалов.
5. Сравните на одном и том же устройстве DER, число голосов, ошибки объединения и разделения, короткие реплики и возвращения после пауз. Замерьте время создания сессии, PSS через `adb shell dumpsys meminfo <package>`, длительность извлечения признаков, медиану и P95 инференса, полное время записи. Включите авиарежим и проверьте работу после холодного запуска.

Сериализованные x86-оптимизации уровня ALL могут зависеть от CPU и набора операторов. Здесь ALL измерялся при запуске ORT, а для отдельного FP32-файла экспортирован только уровень BASIC. Проверки на физическом Android ARM в отчёте отсутствуют. ## Фикстура

В `reports/android_fixture` есть `pcm16.wav` длительностью 1 с и два массива float32 little-endian в построчном порядке. `fbank.f32le` содержит `[1,98,80]`, `embedding.f32le` содержит `[1,192]`. Сначала сравните fbank на телефоне, затем подайте готовый fbank напрямую в ORT и сравните эмбеддинг. Для первой проверки FP32 используйте `atol=1e-4, rtol=1e-3` и косинусное сходство ≥ 0,9999. Источник WAV — первый фрагмент `runs/controlled/test/clean/sources.json`, Mini LibriSpeech CC BY 4.0.
